## Repeat deployment and rollback

Use this queue worktree and the updated README for subsequent deployments.
Migrations are idempotent through `schema_migrations`. Writer activation is a
one-time step and must not be repeated from `legacy` after it is already active.

If rollback is necessary, pause both queue consumers and Cron dispatch, switch
the database writer with `scripts/set-refresh-writer-generation.ts --from
queue_v1 --to legacy` using the production environment file, then restore the
previous Worker version and its cron configuration. Rolling back code alone
leaves legacy writes fenced. Leave the additive schema in place.
